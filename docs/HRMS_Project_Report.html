Human Resource Management System (HRMS) Abstract & Contents

Executive Summary & Abstract

The Human Resource Management System (HRMS) is a lightweight, high-performance console utility engineered to handle fundamental workforce operations without the deployment overhead of external database servers or complex graphical interfaces. Built entirely with Core Java, it emphasizes clean Object-Oriented design, safe state encapsulation, and crash-resilient input validation.

The system features a structured 3-tier architecture: the Model layer (encapsulating employee entity data), the Service layer (governing business operations, duplicate prevention, salary analytics, and CSV persistence), and the Presentation layer (an interactive CLI terminal menu). File durability is guaranteed through standard buffered character streams writing to data/employee.txt. System correctness is validated via 11 automated unit tests in JUnit 5 with a 100% pass rate.

Chapter 1 Introduction & Project Scope

1. Introduction

1.1 Background & Motivation

Human Resource departments across enterprises require reliable software tools to catalog employee rosters, verify unique identities, update compensation structures, and generate payroll metrics. While enterprise ERP systems (e.g., SAP, Workday) cater to large organizations, they carry steep licensing costs, substantial memory footprints, and heavy database prerequisites.

For academic study, internal tooling, and small-scale operations, a self-contained, console-driven Java application offers an ideal showcase of fundamental software engineering principles: Object-Oriented Programming (OOP), Defensive Input Validation, and Reliable File I/O.

1.2 Problem Statement

The goal was to design, construct, and verify a complete, standalone Human Resource Management System in Java capable of performing all essential workforce administration tasks without relying on external UI frameworks or third-party databases.

The application must provide intuitive terminal interaction, prevent runtime exceptions caused by invalid user inputs, maintain data durability across sessions via flat-file persistence, and provide business analytics including gross payroll and salary averages.

1.3 Objectives & Scope

Core Engineering Objectives
Deliver an academically sound, production-grade Core Java application following clean architecture, verifiable through automated JUnit test suites.
  • Robust Data Modeling: Encapsulate employee attributes (ID, Name, Salary) with proper getters, setters, and formatters.
  • Data Integrity & Validation: Enforce unique ID constraints, reject negative salaries, and validate strings.
  • Crash-Resilient CLI: Guard terminal inputs against InputMismatchException and scanner newline bugs.
  • Durable Storage: Serialize employee lists to comma-separated text files (data/employee.txt) with automatic directory creation and error recovery.
  • Payroll Intelligence: Compute total payroll, average salary, highest paid, and lowest paid employees in real time.

3. System Architecture & Design

3.1 Three-Tier Layered Architecture

The application implements a decoupled, three-tier architectural pattern. This ensures high cohesion within classes and low coupling between layers: 

+-----------------------------------------------------------------------------------+
|                            PRESENTATION LAYER (app.Main)                          |
|  - Interactive Menu Controller    - Crash-Proof Input Parsers    - ASCII Renderers|
+------------------------------------------+----------------------------------------+
                                           |
                                           v
+-----------------------------------------------------------------------------------+
|                             SERVICE / BUSINESS LAYER                              |
|           service.EmployeeService          |          service.FileService         |
|  - In-Memory List Management (ArrayList)   |  - BufferedReader / BufferedWriter   |
|  - Duplicate Validation & Search Logic     |  - CSV Serialization & Parsing       |
|  - Real-time Payroll Statistical Engine    |  - Directory Creation & Auto-Recovery|
+------------------------------------------+----------------------------------------+
                                           |
                                           v
+-----------------------------------------------------------------------------------+
|                              DOMAIN / MODEL LAYER                                 |
|                                 model.Employee                                    |
|  - Private State: id, name, salary         - CSV Helpers: toCsvString, fromCsv    |
|  - Accessors / Mutators (Encapsulation)    - Identity: equals() / hashCode()      |
+------------------------------------------+----------------------------------------+
                                           |
                                           v
+-----------------------------------------------------------------------------------+
|                               PERSISTENCE STORAGE                                 |
|                            data/employee.txt (CSV Format)                         |
+-----------------------------------------------------------------------------------+

3.2 Object-Oriented Principles Applied

  1. Encapsulation: All fields in Employee are declared private. State modifications occur only through validated methods (setSalary, setName).
  2. Single Responsibility Principle (SRP): Employee maintains entity data, EmployeeService executes business calculations, FileService isolates disk I/O, and Main orchestrates user dialogue.
  3. Defensive Copying: EmployeeService.getAllEmployees() returns an unmodifiable list copy (Collections.unmodifiableList), safeguarding internal lists from external mutation.
  4. Separation of Concerns: File persistence is parameterized, allowing unit tests to inject temporary directories without mutating production records.

Chapter 4 Component Implementation Details

4. Implementation Details

4.1 Model Layer: Employee.java

The domain model encapsulates employee state and provides bidirectional CSV mapping: 

package model;
import java.util.Objects;

public class Employee {
    private int id;
    private String name;
    private double salary;

    public Employee(String name, int id, double salary) {
        this.name = name; this.id = id; this.salary = salary;
    }
    public int getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public double getSalary() { return salary; }
    public void setSalary(double salary) { this.salary = salary; }

    public String toCsvString() {
        return id + "," + name + "," + String.format(java.util.Locale.US, "%.2f", salary);
    }
    public static Employee fromCsvString(String line) {
        if (line == null || line.trim().isEmpty() || line.startsWith("#")) return null;
        String[] parts = line.trim().split(",", -1);
        if (parts.length < 3) return null;
        try {
            return new Employee(parts[1].trim(), Integer.parseInt(parts[0].trim()),
                                Double.parseDouble(parts[2].trim()));
        } catch (NumberFormatException e) { return null; }
    }
    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        return id == ((Employee) o).id;
    }
    @Override public int hashCode() { return Objects.hash(id); }
}

4.2 Business Service Layer: EmployeeService.java

Governs workforce collections, integrity checks, and analytics:

  • addEmployee(Employee e): Validates unique ID before appending to internal list.
  • findEmployeesByName(String q): Performs case-insensitive substring search.
  • getTotalPayroll() & getAverageSalary(): Computes statistical metrics dynamically.
  • printEmployeeTable(List): Formats employee rows into an ASCII tabular grid.

Chapter 5 Data Persistence & Storage Architecture

5. Data Persistence & Storage Architecture

5.1 Flat-File Storage Architecture

The persistence subsystem is implemented in FileService.java. The system utilizes Comma-Separated Values (CSV) instead of Java binary object serialization. This delivers human readability, interoperability with external spreadsheet tools, and zero vulnerability to InvalidClassException during class evolution.

File Location & Schema
Persistent storage path: HRMS/data/employee.txt. Directory is dynamically created upon first run.

5.2 CSV Data Specification

Lines starting with # denote comment or header metadata. Data rows follow the strict format: ID,Name,Salary: 

# ID,Name,Salary
1,Snehil,100000.00
2,Dhyey,200000.00
3,Kartikey,110000.00
4,Kislay,150000.00

5.3 Persistence Mechanics in FileService.java

public boolean saveEmployees(List employees) {
    File file = new File(filePath);
    File parentDir = file.getParentFile();
    if (parentDir != null && !parentDir.exists()) parentDir.mkdirs();

    try (BufferedWriter writer = new BufferedWriter(new FileWriter(file))) {
        writer.write("# ID,Name,Salary");
        writer.newLine();
        for (Employee e : employees) {
            writer.write(e.toCsvString());
            writer.newLine();
        }
        return true;
    } catch (IOException e) { return false; }
}

5.4 Fault Tolerance & Recovery Features

  • Automatic Directory Creation: Invokes parentDir.mkdirs() if data/ is absent.
  • Resource Safety: Uses Java try-with-resources to guarantee closing stream descriptors.
  • Corrupt Line Resilience: Skips empty, malformed, or non-numeric records gracefully.

Chapter 8 Conclusion, Future Scope & References

8. Conclusion & Future Scope

8.1 Project Conclusion

The Human Resource Management System (HRMS) successfully demonstrates how core Java technologies and disciplined software engineering practices can deliver a robust, functional workforce utility without unnecessary graphical baggage or external database engines.

Key engineering outcomes achieved:

  • Strict Encapsulation: Complete separation between domain entity representation and service logic.
  • Defensive Programming: Comprehensive input validation safeguarding against runtime scanner failures.
  • Persistence: Human-readable, fault-tolerant CSV file persistence supporting automatic loading and saving.
  • Empirical Verification: 11 automated JUnit 5 tests confirming 100% functional correctness.

8.2 Future Scope & Enhancements

  1. Relational DB Integration: Upgrading from CSV flat files to SQLite or PostgreSQL via JDBC / JPA.
  2. Authentication & RBAC: Adding administrative logins and role-based operational permissions.
  3. Web RESTful Services: Wrapping the service layer with Spring Boot to expose REST APIs for mobile/web apps.
  4. Departmental Organization: Extending the Employee entity with department hierarchies and leave tracking.
